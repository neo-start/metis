# Metis 局域网设备协作

两个独立 Metis 实例可以用实例 ID 配对，双向发送消息和委派任务。每个实例保留自己的数据库、项目、模型凭据和任务执行权限。

## 配对与使用

1. 两台电脑都打开「设置 → 手机与远程连接 → 我的设备 · 局域网协作」，开启协作。
2. 选择本机接收任务所用的会话配置并保存。新任务使用该会话的项目、模型和权限模式，但在独立会话中执行，不向原会话插入任务。不选择配置时只接收消息。
3. 在 A 输入 B 显示的完整实例 ID，点击「请求配对」。同一局域网通过 mDNS/DNS-SD 发现地址；也可以选择附近设备。发现受限时填入 B 显示的备用 IP 和端口。
4. 在两个界面核对相同的校验码，在 B 确认配对。请求有效期为 5 分钟。双方保存信任关系，后续自动重连。
5. 在设备列表发送消息或委派任务，也可以在支持 Metis Gateway 的 Agent 会话中说「让另一台 Metis 完成这个任务」。旧的运行中 Provider 会话可能需要新开会话才能看到新增工具。

需要允许系统防火墙接受 Metis 的入站连接。访客 Wi-Fi、AP 隔离或不同广播域可能阻止发现或直连。实例 ID 不能穿透被网络策略隔离的设备；本版本没有云端目录和中继。

## Agent 工具

- `metis_devices`：查看已配对设备、连接状态、消息和任务。
- `metis_peer`：`status` 查看接收项目与任务状态；`message` 发消息；`task` 委派任务；`cancel` 请求取消。
- `message` 不带 `taskId` 时进入设备收件箱；带 `taskId` 时，消息会排入该任务的执行会话或发起会话，用于跨设备提问和回复。接收端核验该任务确实属于发送设备。
- 重试消息或任务应沿用 `requestId`。网络失败后请求可能已被对方接收；本地发件箱会重试，不应换 ID 重复派活。
- Agent 委派的任务完成后，结果自动排入发起会话。设置页发起的任务结果在设备列表查看。需要本机审批或回答时显示等待状态，应在执行设备的对应会话处理。

接收端一次执行一个远程任务，其余持久化排队。现有本地任务仍可能并行操作同一个项目，因此选择接收项目时应避免与其他任务同时修改同一文件。本版本不自动创建 Git worktree、不迁移文件、不复制 Provider 凭据。结果回传为文本，远程路径仍属于远程设备。

## 身份、授权与传输

- 实例 ID 是本地证书 SHA-256 的前 128 位，形如 `metis-…`。首次连接先校验证书与输入 ID 一致，再发送配对请求；校验码同时绑定双方身份与本次请求。
- 每个实例有独立 TLS 身份。局域网通道使用 TLS 1.3 双向证书认证，配对后固定对方证书。首次配对只允许有限的配对接口，未配对设备不能访问任务和消息。
- mDNS 广播只包含公开的实例 ID、设备名称、协议版本和监听端口。IP/端口可变化，身份不随地址变化；手动地址仅接受局域网或回环 IP。
- 协作默认关闭。开启后独立 HTTPS 监听器绑定 IPv4 网络接口，接受局域网来源；应用原来的 HTTP/WebSocket 管理监听配置不变。当前任务进度通过周期查询同步，不依赖持续 WebSocket 连接。设备通道要求 Node.js 后端；桌面与 `metis:serve` 已使用 Node。直接用 Bun 启动开发后端时，由于其入站 socket 不提供客户端证书，该功能拒绝开启。
- 所有配对、配置、撤销和手动通信操作通过原有 owner WebSocket 会话进入。Agent 只能在已配对设备间操作，不能自行配对或授予信任；写工具仍校验当前执行轮次。
- 接收任务继承本机所选会话的审批模式。远程内容不能改变该模式；收取结果不会提升权限。入站任务不能再次跨设备委派，避免环形派活。
- 解除配对立即拒绝后续请求并移除发件箱里的待发请求。尚未开始的关联任务停止；已经开始的本机任务需在对应会话取消。关闭协作只关闭通信与队列调度，不终止已运行的 Provider。

## 持久化与恢复

运行状态目录的 `peers/identity.json` 保存本机私钥和证书，`peers/state.json` 保存设置、信任证书、消息、任务、发件箱和结果通知回执，使用既有私有原子写入机制。不要复制该目录来创建第二个实例，否则会复制同一身份。证书当前有效期十年；到期更换身份后需要重新配对。

任务先持久化再确认收件；稳定请求 ID 防止重复创建。任务引擎的持久化命令回执用于处理「已执行但尚未写回协作状态」的崩溃窗口。断线时执行端继续工作，发起端显示连接错误并保留最后一次已知状态，重连后同步结果。取消只有在执行端受理后才生效；连接中断不会被当成取消成功。

验证使用临时目录和真实回环 TLS 连接，不访问日常 Metis 数据、不调用付费模型。跨物理设备的防火墙、mDNS 和实际 Provider 行为需要在两台已安装该版本的电脑上验收。
