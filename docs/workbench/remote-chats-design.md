# Remote：与另一台电脑的总控对话

状态：2026-10-14，实例身份、固定总控入口、记忆版本和经验整理已实现于源码，见 [实例总控](metis-controller.md)；本文的 Remote 聊天界面与远端协议仍是待实施设计。

## 用户澄清：每个实例都有自己的 Metis

用户明确要求：每个 Metis App 都实例化一个长期存在的 Metis 总控，可以获取本实例所有对话内容，拥有 memory 和 soul.md，并持续进化成长。这取代下文早期“挑选普通会话充当总控”的设计；普通会话只是与总控交互的载体。

- **身份与生命周期。** 每个独立数据实例有一个持久总控身份，首次使用自动初始化，重启恢复。多个窗口连接同一后端时仍是同一个 Metis。身份独立于模型、Provider 和某条聊天线程；换模型、会话压缩或接续不会生成一个失忆的新总控。
- **全局理解。** 总控可检索本实例全部保留的会话，包括项目聊天和归档历史，并读取原文核实。全量可访问不等于每轮注入全量内容：通过会话索引、增量摘要和按需读取保持成本与上下文可控。删除的内容不能被记忆维护任务悄悄恢复。
- **灵魂与记忆。** 复用现有实例级 memory/soul.md、global 和 projects 存储。soul 描述身份、职责、风格与长期原则；memory 保存用户偏好、项目知识、经验、决策及待办。记忆保留来源、时间与修订轨迹，允许纠错、删除和回退。
- **持续成长。** 在会话结束、任务完成、失败或用户纠正后增量整理经验，合并重复项、修正过时信息，并在后续决策中读取。持久保存处理游标，合并事件、限制后台工作预算，避免重启后反复总结全部历史或无变化时不断调用模型。成长意味着记忆、策略与可复用能力积累，不声称模型权重在本机持续训练。soul 的演进需有独立版本记录，不能将某次任务输出直接覆盖为长期人格。
- **统一入口。** 本地 UI、飞书和已授权 Remote 都接入该实例总控。不同来源保留可辨认的会话与任务上下文，共享总控身份和长期记忆；默认不因共享身份而把所有私人历史广播给每个远程设备。Remote 连接的是对方的 Metis 实例，由对方总控协调本机任务。

当前代码在已有实例级 soul/memory 和跨会话工具之上，增加了独立身份、总控入口、handoff 接续及持久化经验整理批次。普通 Agent 的项目记忆范围保持不变；指定总控通过 metis_self 跨项目读取记忆，并以版本检查修订 soul。详细已实现行为和限制以 [实例总控](metis-controller.md) 为准。

## 用户体验

在左侧 Chats 下增加同级 Remote 分组。设备配对成功后，每台设备显示一个总控入口；点击后在当前主区域打开普通聊天界面。新增设备入口复用现有配对流程。两端各自保留本地 Chats，也能打开对方的总控。

```text
Chats
  Metis 总控
  其他本地会话
Remote                          +
  MacBook Pro · 总控             在线
  Mac mini · 总控                离线
```

这里的设备名称仅为布局示例。真实设备、在线状态和未读提示必须来自后端，不以配对记录代替实时连通状态。

用户要求 UI 与本地对话一致：复用相同的聊天标题栏、消息时间线、输入框、执行过程、追问和停止控件；字体、颜色、间距、键盘行为与设置一致。标题栏补充设备名称和连接状态，让执行位置始终明确。远端能力未开放时使用现有控件的禁用或说明状态，不提供会误操作本机的按钮。

Remote 默认连接对方实例总控的持久对话入口，连续追问保留该对话上下文；不是每发一条消息创建一个新任务。接收端也能看到来自另一台电脑的消息，并辨认其设备来源。总控身份与入口线程分离，线程接续时远程绑定仍跟随同一总控。

## 已有基础与缺口

已有 [局域网设备协作](lan-peers.md) 提供实例 ID、发现、配对、mTLS、持久化发件箱、任务去重、状态查询、取消和结果回传。继续使用这些实现及其信任边界。

当前 `message` 没有 `taskId` 时只进入设备收件箱；`task` 使用配置模板新建执行会话；带 `taskId` 的消息可以进入关联执行会话或发起会话。这些行为不能直接满足“打开对方现有总控持续聊天”。当前结果同步也不等于完整聊天历史、工具活动和审批同步。

前端 `nativeApi.ts` / `wsNativeApi.ts`、`store.ts` 和普通聊天路由目前基于单个本机后端。不能简单切换全局连接地址，否则本地 Chats、缓存、草稿及其他打开的面板会受到影响。

## 实现边界

1. **实例总控入口。** 为系统总控建立独立于任务模板的持久入口，不改变 `templateThreadId` 的任务模板语义。配对本身不自动公开所有历史会话。解除配对时旧绑定立即停止访问；总控内部会话接续通过受控映射保持身份连续。
2. **扩展受限 Peer 协议。** 增加总控元信息、分页历史、增量事件、发送、停止和已开放审批/问题响应。服务端自行解析已授权绑定；不能允许调用方凭任意 `threadId` 读取或控制其他会话，也不能透传整个管理 RPC。
3. **按来源隔离客户端。** 会话标识使用 `(instanceId, threadId)`；请求、查询缓存、草稿、订阅游标和消息去重均带设备作用域。本地与远端同名或相同 ID 不发生串线。每个实例只有一个连接重试所有者。
4. **复用普通聊天。** 从现有 ChatView 及相关 hooks 抽出明确的会话数据/命令适配边界，本地与 Remote 都使用它。复用现有 Sidebar 分组、行、菜单和 disclosure 动效，不复制一份独立聊天实现。
5. **可靠发送与恢复。** 稳定请求 ID 贯穿发送与远端引擎命令回执。断线显示未确认状态，重连按游标补齐事件；不重复派活。任务仍在执行端运行，断线不等于取消。停止指向观察到的具体远端 turn，避免延迟命令误停下一轮。
6. **双向协作。** 用户直接打开对方总控，和本地 Agent 委派任务，继续分别走会话通道与现有任务通道。沿用结果回传与防循环约束，不能让同步回来的每一条 assistant 消息自动触发双方无限回复。
7. **执行归属。** 模型、账号、工具和文件操作使用执行电脑的配置。远端文件路径不能交给本机文件 API；附件传输、预览与下载需显式路由至所属设备。未实现传输前不得把远端路径显示为本机可用附件。

配对后的日常发消息、追问和派任务不重复询问连接授权。执行端既有工具审批仍按原权限策略处理。

## 验收条件

- A 的 Remote 打开 B 的指定总控；B 同样能打开 A，连续追问保留对应会话上下文。
- 本地和远端使用相同聊天组件，消息、执行过程及可用操作表现一致。
- 两端同时发送遵循执行端排队规则；重试、重启和断线恢复不重复执行。
- 停止、审批和问题回答严格作用于指定设备、会话和执行轮次。
- 撤销配对或更换公开会话后，旧请求和订阅不能继续读取或写入。
- 本地草稿、历史、项目与远端状态互不覆盖；远端文件不误走本机工具。
- 后端使用隔离目录做相关单元及协议验证；按项目规则不主动执行前端测试或浏览器 QA。两台物理电脑的实际连接与模型执行须单独记录验证结果，不能用回环测试替代。

尚未添加 Remote UI、修改 Peer 通信协议、重启日常应用或向远端派发任务。
