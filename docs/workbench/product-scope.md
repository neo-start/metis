# 统一 Agent 工作台：功能范围草案

更新：2026-09-23。

## 用户已经明确的方向

用户希望同时拥有 T3 Code 和 Synara 的功能，继续探索自己的产品。此前已试用并拒绝 Emdash。当前保留两者核心能力的整体范围，不将建议缩减为二选一。

下述功能分组、交互组织和开发顺序是助手提出的草案；用户尚未逐项确认。未确定项目名称、代码底座、商业模式、团队协作或原生手机应用。没有创建源码仓库、安装软件或开始实施。

## 产品定义

以项目和任务为中心的统一 Agent 工作台。在 Mac 上使用已配置的 Agent 处理工作，集中查看过程与成果；网页和手机可以连接执行环境，查看和继续同一项任务。

首个使用场景暂按个人使用、Mac 为主要执行机器设计。多用户权限、组织管理和收费体系待确认，不自行加入首版。

## 完整功能目标

| 能力              | 期望行为                                                          | 需要明确的边界                                                     |
| ----------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------ |
| 多 Agent 统一会话 | Codex、Claude Code 等共用项目与会话入口；每次执行能识别所用 Agent | 统一展示不代表各 Agent 的工具和权限完全相同                        |
| 过程与控制        | 流式回复、工具步骤、附件、问题与授权、中断和恢复                  | 已发出的命令和写入不能因断线被重复执行                             |
| 历史管理          | 搜索、导入和恢复已有本机会话                                      | 清楚标识原会话与独立副本，逐项确认附件/工具记录的保留程度          |
| 工作区            | 现有目录、文件浏览/编辑、终端、diff、Git/PR、浏览器预览           | 默认沿用指定目录；隔离 worktree 由用户选择；遵守项目级限制         |
| Agent 交接        | 同一任务按阶段换 Agent，显示传递的目标、约束、进展和文件          | 接收者获得明确交接内容；不承诺内部上下文无损迁移                   |
| 并行工作          | 同时进行多个任务，明确各自目录、状态和文件归属                    | 区分任务交接与并行编辑；不能让共享目录的冲突悄悄发生               |
| 多端接续          | 桌面、Web、手机看到同一任务，远程查看进度和继续沟通               | 执行机器离线时明确不可继续执行；先验证手机浏览器，再决定原生客户端 |
| 自动化            | 定时/重复任务、执行历史、通知、暂停与恢复                         | 后台服务负责持续执行；窗口关闭与服务关闭要区分                     |
| 成果管理          | 代码、报告、文档、图片等集中预览和查找，支持长期项目              | 区分过程文件与交付成果，保留来源与版本信息                         |
| 配置接入          | 尽量沿用原 Agent 的 skills、MCP、hooks 和设置                     | 兼容程度按 provider 验证；不自动宣称全部互通                       |

## 交互草案

- 左侧：项目、最近会话、运行中的任务；保留搜索和恢复入口。
- 中间：主要对话、执行步骤、用户需要处理的问题与授权。
- 右侧：按需打开文件、成果、预览、diff 或终端；平常可收起。
- 自动化与长期成果各有独立入口，普通任务不需要填写整套高级配置。
- 手机优先展示状态、回复、授权、停止和成果预览；代码编辑等高密度操作按设备能力安排。

## 实现原则草案

选一套主要实现基础，统一项目、任务、会话和数据模型。分别评估复用现有项目与自行实现的代价，再决定代码来源；本轮没有选定 fork 对象，也未承诺直接合并两个仓库。

执行服务持有任务的权威状态，桌面和远程客户端显示同一份记录；Agent 接入独立适配。后台运行、重连、审批、附件和会话恢复从数据设计阶段考虑，避免以后为多端另造第二套历史。

## 建议交付顺序

1. **本地任务闭环**：已有目录 + Codex/Claude + 对话/附件 + 过程/授权 + 文件成果 + 中断/重开继续。验证一个真实任务从开始到交付。
2. **接续与交接**：本机历史导入、Agent 交接、Web/手机连接、断线重连；验证同一任务和同一文件状态能被正确恢复。
3. **扩展使用场景**：更多 Agent、并行任务管理、自动化、长期成果工作区和更完整的开发工具；根据实际使用调整先后。

这是实现顺序，不删除完整功能目标。具体迭代范围与验收方式需在选定交互后细化；不据此承诺工期或功能全等于两个快速变化产品的每个细节。
