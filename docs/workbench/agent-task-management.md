# Agent 任务管理

这组功能借鉴 Herdr 的任务运行与状态管理方式，继续使用 Metis 的结构化会话、权限和工具体系。

| 功能         | 入口                            | 行为                                                                               |
| ------------ | ------------------------------- | ---------------------------------------------------------------------------------- |
| 默认持续运行 | `npm run metis`                 | macOS/Linux 自动启动或连接共享后台，退出桌面后任务继续；显式停止后台才结束服务。   |
| 待处理事项   | 侧栏 Activity → Needs attention | 汇总审批、问题、结果验收和异常；打开现有交互面板处理，直接查看 Diff 或标记已处理。 |
| 任务控制接口 | 设置中的外部 MCP 连接           | 创建、读取、等待、发送后续消息、回答、审批和中断；新增操作需要单独授权。           |
| 多机任务     | 侧栏「设备任务」及设备设置      | 显示执行设备、进展、结果和同步时间；支持已配对设备之间的所有者审批与回答。         |
| 原生 CLI     | 任务终端 → Agent terminal       | 输入 CLI 命令，在任务环境启动、重新连接或停止；无需 Provider 适配器。              |

## 运行与停止

源码变更后先运行 `bun run build:desktop`，再运行 `npm run metis`。
如果旧版桌面仍独占后台，先退出旧桌面；不要同时启动两个后端访问同一个数据目录。
退出新版桌面只断开客户端。需要结束后台时，使用桌面菜单中的停止后台操作，或：

```sh
npm run metis -- --stop-background
```

`--dev` 和 `--web` 保留开发模式的生命周期，Windows 暂未启用默认共享后台。
持续运行不代表休眠、关机或后台崩溃后原进程还能执行。浏览器和电脑控制工具仍依赖桌面 host 在线；普通后台任务与 Gateway 不需要改为功能受限的原生 Codex 宿主模式。

## 权限与状态

待处理事项使用已有会话状态与交互记录，不从终端文字猜测审批或完成状态。
审批和回答进入已有的 Provider 流程；查看结果与标记已处理不会自动批准操作。

外部 MCP 原有连接不会自动获得新权限。在创建连接时，按需要开启后续消息、回答、审批或中断；只读其他项目任务的权限不等于允许修改这些任务。
调用方应保留稳定请求 ID 与请求内容，网络超时后使用同一请求重试，避免重复执行。

跨设备任务只使用已经配对的设备通道。所有者可以处理支持该能力的执行设备返回的待审批或待回答事项；Agent 工具不能代替所有者远程批准。
断线后保留最后状态并标记可能过期，重连后自动同步。旧版本设备继续支持原有功能，未提供远程响应能力时在执行设备处理。

原生 CLI 运行在任务终端权限下，由 CLI 自己管理登录与权限。它不提供 Metis 结构化审批、用量统计或会话交接；重新连接不会自动重发启动命令。
