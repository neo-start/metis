# 实例级 Metis 总控

每个独立数据目录拥有一个持久的 Metis 身份。连接同一后端的多个窗口共享这个身份；不同电脑或隔离的数据目录各自拥有身份、soul 和记忆。

## 入口与生命周期

左侧固定的「Metis 总控」打开普通聊天界面，使用原有 ChatView、输入框、模型选择、审批和任务工具。设置 → Memory 显示实例 ID、成长开关和最近一次整理结果。

后端首次加载创建 `<stateDir>/metis/identity.json`。已有 `metis-console` 容器中的活动「Metis 总控」会被接续，保持原来的模型、权限和历史。没有既有总控时，所有者界面首次连接会创建一条置顶总控会话，沿用普通新聊天的最近模型选择和默认权限；创建本身不调用模型。

身份独立于线程。模型 handoff 通过已有的 sourceThreadId 链寻找后继，身份 ID 保持不变。归档或删除总控会话不会恢复被删除的历史；下次所有者界面同步或打开时创建新的对话载体，保留实例身份和长期记忆。并发窗口由服务端串行处理，稳定创建 ID 处理创建已提交但身份文件尚未保存的崩溃窗口。

只有当前绑定的总控获得 `metis_identity` host 上下文和总控专属工具权限。其他会话共享实例 soul 和普通记忆，但不会仅因标题相同或写入某条记忆就成为总控。

## 记忆与成长

复用 [现有 memory 存储](../memory.md)。首次启动仅在 soul.md 不存在时写入默认身份与工作原则，不覆盖用户已写的内容或刻意留空的文件。普通 Agent 继续读写全局记忆和自身项目记忆。

总控通过 `metis_self`：

- `overview`：查看实例身份、总控入口和整理状态。
- `memories` / `read_memory` / `write_memory`：查看各项目记忆索引、按需读取正文并将项目经验保存到对应项目。
- `soul`：读取灵魂正文及 SHA-256 版本。
- `evolve_soul`：根据有依据的反馈修订长期原则；必须提供读取时的版本与原因，拒绝过时版本、无活动轮次或无写权限的请求，也拒绝凭据内容。
- `complete_reflection`：仅整理批次自己的执行轮次可确认完成，写入结果与来源记录后推进处理游标。

总控通过既有 `synara_list_threads`、`synara_read_thread` 等工具访问本实例保留的对话，归档历史可以显式列出。全量可查阅不意味着每轮全部注入上下文。

持续成长默认开启，可在设置关闭。每 30 秒检查总控是否空闲，有用户消息待执行、审批或问题待处理时不派发维护。每小时最多自动处理一批，每批最多十个有新完成轮次的会话；没有新增内容不调用模型。使用总控自身的模型和权限，整理在总控聊天中可见，也可以用普通停止按钮中断。

一次整理会按需核对来源，更新可靠的用户偏好、纠正与经验；没有值得长期记忆的事实也可完成。后台整理期间 Gateway 限制为会话读取、记忆维护和 metis_self，拒绝通过 Gateway 派活、发消息或执行其他操作；这不是对 Provider 原生工具的独立沙箱，原有执行权限仍然生效。

批次先持久化再派发，复用引擎命令回执防止重启后重复执行。失败、中断或未确认完成的批次暂停，设置页显示状态，并提供「现在整理」重试。成功后才推进来源游标。总控自身及其接续线程不作为下一轮整理来源，避免自我总结循环。

## 来源与版本

普通记忆工具自动为正文添加来源会话与轮次。整理结果保存在 `<stateDir>/metis/reflections/<batchId>.json`，其中包含来源列表与结果摘要。

memory 和 soul 修改前，旧内容保存到 `<stateDir>/memory/history/<path-hash>/<content-hash>.json`。这些私有文件不参与记忆注入；其中的 `path` 和 `content` 可用于人工核对及恢复。当前没有单独的版本浏览/一键恢复界面。通过设置或记忆工具删除一条记忆时同时清除该文件的旧版本，避免“忘记”后仍保留可恢复正文。

应用内 soul 写入串行化，并提供版本检查；直接使用外部编辑器修改文件不参与应用锁。新 soul 自动注入新 Provider 会话，已有会话可使用工具读取最新内容。

## 与 Remote 的关系

实例身份是后续 Remote 总控连接的目标，不能再以任意普通聊天标题充当身份。现有局域网配对、消息和任务委派继续保留。本次实例总控实现没有增加 Remote 聊天面板、远端完整历史/事件订阅或远端总控绑定；这些接入边界见 [Remote 设计](remote-chats-design.md)。

验证使用临时数据目录、内存 SQLite 和真实任务引擎，不调用实际模型。类型检查、构建和单元测试不等价于已在日常应用启用，也不证明后台模型整理的实际效果。
